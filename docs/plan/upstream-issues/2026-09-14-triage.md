# mrab-regex open issue re-triage (74 open, live snapshot 2026-09-14)

S49, phase 6. The 2026-08-31 triage in `docs/plan/2026-08-31-upstream-issue-triage.md` was a
point-in-time reading of a moving list; this is the live re-triage the slice asked for, against
`docs/plan/upstream-issues/2026-09-14-open.json`.

**Class key.** A = not a bug (feature or doc request, support question, user error, works as
documented). B = Python-specific or API-shape, so it cannot exist in a C# port (packaging,
build, typing stubs, test plumbing, CPython globals). C = claims an engine or parser bug this
port would inherit. There is no class D: every issue the old triage could not judge has been
run, and the run decided it.

## How this triage was produced

The classification is not a copy of the 2026-08-31 one. A subagent was given the 74 issue bodies
and comments with no sight of the old classes and asked to classify from the text alone; the two
readings were then diffed. They agreed on 60 of 74; the 14 disagreements are adjudicated
in this file, and two further rows were overturned against BOTH readings by a measurement
(367, 589). Every class C issue was then run against `regex` 2026.9.10 and against this port.

Evidence, all re-runnable from the committed tree:

- `python tools/probes/upstream-issue-sweep.py` - every class C case on `regex` 2026.9.10.
- `pwsh -File tools/probes/port-issue-sweep.ps1` - the same cases on this port (needs a Debug build).
- `python tools/probes/pcre2-partial-truncation-assertions.py` - PCRE2 10.47 on issues 367 and 589.

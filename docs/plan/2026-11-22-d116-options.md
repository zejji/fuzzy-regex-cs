## 1. Terms and mechanism

- **BESTMATCH** (`(?b)`) asks for the match with the fewest errors, not the first that fits.
- The **walk** is `Matcher.DoBestFuzzyMatch` (`Matcher.cs`:27369; upstream `do_best_fuzzy_match`,
  `upstream/src/_regex.c`:17584). After finding a match it searches again from that match's start
  with the error budget one below, looking for a better match. With no better match, that search
  fails only at the end of the text, once per match of a `finditer`: quadratic.
- The **memo** (D115, F107; not upstream's) is `Matcher.BestWalkKnownToFail` (`Matcher.cs`:27209,
  called at :27535). Once a search from F has failed under some budget, a later search from S, past
  F, under a budget no wider, runs only its first attempt. The facts live in
  `MatchState.BestWalkFailures` (`MatchState.cs`:1047) for the whole scan.
- `Matcher.BestWalkCanRemember` (`Matcher.cs`:27300-27311) is the gate. It refuses four things:
  partial matching (`PartialSide`), a `\G` anywhere (`PatternObject.ReadsTheSearchAnchor`, set at
  `PatternObject.cs`:1604-1607), a backtracking verb (`HasBacktrackingVerb`), and, since D116, a
  lookaround against the scan whose body can run a fuzzy item (`LooksBackAtTheAnchor`, set by
  `NodeCompiler.NoteABodyThatCanReachTheAnchor`, `NodeCompiler.cs`:1452, called at :1060 and
  :1523).

## 3. How `\G` reads the anchor in this port

`\G` is `Opcode.SearchAnchor`, tested at `Matcher.cs`:4183 against `BackslashGPosition`
(:4201-4212). Since D79 that position is `MatchState.OperationStart`, set once per matching
operation in `DoMatch2` (:28198): for a `finditer`, the position the scan resumed from. The walk's
re-runs move `SearchAnchor` but not `OperationStart`. Upstream instead reads `search_anchor`, which
every re-run's `init_match` moves (`_regex.c`:3410, per the `MatchState.OperationStart` comment);
the oracle-only switch `AnchorsBackslashGAtEveryCandidate` restores that. The search-start fast
path for a leading `\G` (:15272-15281) fails a search that starts past that position.

Other engines agree on what `\G` means in a global search, which is what D79 follows. .NET: "The
match must start at the position where the previous match ended, or if there was no previous
match, at the position in the string where matching started"
(learn.microsoft.com/en-us/dotnet/standard/base-types/anchors-in-regular-expressions, fetched
2026-11-22). PCRE2: "The \G assertion is true only when the current matching position is at the
start point of the matching process" (pcre.org/current/doc/html/pcre2pattern.html, fetched
2026-11-22). None of them has a best-match walk, so none faces this memo question; the 2026-11-16
note's survey (RE2 and .NET NonBacktracking support no lookarounds; PCRE2's
`PCRE2_INFO_MAXLOOKBEHIND`; the PLDI 2024 lookaround table) covers the lookbehind side.

## 4. Options

Every option must keep every answer identical to main: the memo is an optimisation beyond upstream.

### G. Remember `\G` patterns unless `\G` sits in a body against the scan (recommended)

**How.** Stop refusing every `\G`. Instead treat `Opcode.SearchAnchor` like a fuzzy item in
`NoteABodyThatCanReachTheAnchor`: a `\G` inside a lookbehind (or a reversed pattern's lookahead, or
such a conditional test) sets `LooksBackAtTheAnchor`; a `\G` anywhere else sets nothing.
`ReadsTheSearchAnchor` then leaves `BestWalkCanRemember`.

**Why it is sound.** Take a fact from a search from F and a later search from S (past F, scan
direction), and an attempt at T past S, which the memo skips. Call G1 and G2 the `\G` positions of
the two searches. Both lie at or before S: G2 is the later operation's start, at or before the
walk's start S; G1 is at or before F. Outside a body against the scan, the attempt's text position
only moves away from T, so it is always past S and never equals G1 or G2. So `\G` fails at every
point of that attempt in both searches, and the attempt runs the same in both, as the memo's
existing argument needs. Under the oracle switch, G is the search's own start (F or S), and the
same holds. The fast path at :15272 runs identically in a one-attempt search and a live one. Inside
a body against the scan the argument breaks: `(?<=\G.{0,3})` at T can read back to G2 when T is
within 3 of it, and G1 differs from G2 when the two facts come from different `finditer` steps.
Five hand-written witnesses for that case (`.scratch/d116r/probe3.cs`, log `run3.log`, for example
`(?b)(?:(?<=\G.)x|ab){e<=1}` over `aXax`) did not change an answer with the flag forced off. So the
exclusion has no witness yet. VERIFICATION rule 12 then needs either a witness found by a grid, or a
written argument that none can exist. Until one of them exists, keep the exclusion; it costs nothing
measurable.

**Rule 10 item for the builder.** The `AnchorIsPinned` assertion (`Matcher.cs`:4248-4255) lets any
pattern with `ReadsTheSearchAnchor` through. Find out why before narrowing it. A likely cause is the
fast path at :15280, which moves an attempt's start to the `\G` position. If a fuzzy item can then
meet `SearchAnchor` on an attempt that did not start there, the memo's premise needs re-checking for
that case.

**Worst case.** No new cost: one flag computed at compile time. A pattern G still refuses is no
worse than today.

**Adversarial input for correctness.** A `\G` reached through a group call (the called group is
compiled elsewhere, so it is not among the body's nodes: already counted as "can reach" by the call
rule); `\G` in a nested lookahead inside a lookbehind (covered, since the whole body is scanned);
`(?br)` with `\G` at the end; `\G` with an empty-match ban after an empty match (`MustAdvance`,
already a fact key).

**Size and risk.** Small (estimate: under 20 lines plus tests), no engine control flow change,
faithful-port structure untouched. Risk: low, once the assertion question above is answered.

**Value.** Low today: 0 of the 4 corpus patterns with `\G`
(`tests/FuzzyRegex.Tests/Gaps/CompileParity/corpus.json`: `\G\w{2}`, `(?r)\G\w{2}`,
`(?r)\w{2}\G`, `.{2}(?<=\G.*)`) is fuzzy, and the corpus is upstream's test suite, not a survey of
real use. The case for building it is that it removes a quadratic cliff on a supported feature at
almost no cost.

### A. Bounded reach for fuzzy lookbehind bodies

Unchanged from the 2026-11-16 note, section 3 option A: compute at compile time how far back any
fuzzy item in a body against the scan can read (R, in UTF-16 units, over the whole nested body),
and run the attempts from S to S + R live instead of only the first one. Worst case O(n x R) per
scan instead of O(n x n). Measured today: this class is quadratic (29,912,998 steps at 16,000
characters against 206,141 for the control). Risks as recorded there: getting R wrong for
non-BMP text or full case folding gives a wrong answer, not a slow one. Value: 2 of 49 corpus
patterns with a lookaround against the scan. Not recommended now.

### C. Leave recursive calls in a body against the scan as they are

A call the inliner keeps has unbounded reach, so A cannot cover it. With the inliner in place this
class is only recursion, the inliner's size cap, and the oracle switches. Recommended: keep the
memo refused for it and record it as the ceiling.

### D. Do nothing more

Close the remainder with this measurement on record. Cost: `(?b)` `finditer` patterns with `\G`
stay quadratic (9,411,085 steps at 16,000 characters of prose against 171,106 for the same pattern
without `\G`). Acceptable if G's assertion question turns out to be expensive to settle.

### Summary

| Option | Covers | Worst case | Size | Risk |
|---|---|---|---|---|
| G | `\G` outside bodies against the scan | no new cost | small, compile time | low |
| A | fuzzy bodies with bounded reach | O(n x R) per scan | moderate, new reach analysis | medium |
| C | (refuse) recursive calls | quadratic, as today | none | none |
| D | nothing | quadratic for `\G` | none | none |

## 5. Correctness risks per feature, for option G

- **Fuzzy:** G changes no fuzzy matching; facts are still keyed by error and cost budget.
- **Captures:** the memo skips only attempts that fail, so no capture is reported from a skipped
  attempt; unchanged.
- **Partial:** still refused by `PartialSide`; unchanged.
- **Reverse:** `(?br)` mirrors the argument ("past" means further left); one witness row above,
  needs grid coverage.
- **`(?b)` and `(?e)`:** the memo runs only in the BESTMATCH walk; ENHANCEMATCH is untouched.
- **Lookarounds:** the one place G still refuses; see section 4.

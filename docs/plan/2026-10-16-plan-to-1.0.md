## 3. Correctness: the battery and the stopping rule

**The battery** (one run takes about 3-4 hours wall time; it is not timing, so it runs day or night):

| Search | Finds | Reference | Tool |
|---|---|---|---|
| Oracle, 10 fresh seeds per run, 2,000 rows each, Debug invariants on | port bugs vs upstream | regex 2026.9.10 | `tools/sweep-seeds.ps1`, `run-oracle.ps1` |
| Real-pattern bed, 276,591 rows (3,096 Lingua Franca patterns + 7,000 generated) | inherited bugs | Python `re`, `mini.py` | `.scratch/s1016/d85/bed/` |
| Feature-pair generators, one per cell: fuzzy x {backref, lookaround, atomic, verbs, conditional, `\K`, reverse, partial}; `\K` x each cut; backref x repeat; partial x {lookaround, atomic, verb, fuzzy}; reverse x each | interaction bugs | guards-off control, `re`/PCRE2/Ruby where they accept the pattern, the fuzzy reference matcher | new generators in `tools/battery/` (from `n3/gengaps.py`, `genw.py`, `gen_b3.py`) |
| The complete matrix on two new seeds | regression of known cells | three engines (C7) | `tools/matrix/` |

**Each run's output** is a triage table: new root causes (registered at once), known causes, decided
rules. A root cause is fixed test first (red test, fix, differential against main, oracle x3,
ratchet, blind review for anything over ~50 lines), or refused under decision 2.

**Fixes must not bring obvious performance regressions (owner, 2026-10-16).** Performance work is
frozen (decision 3), but a correctness fix still has to avoid making things slower where that can be
avoided. Reasoning is used to find the cases worth checking (which patterns now take a slower path,
what the worst case grows as, an adversarial input), and every such case is then measured, never
settled by reasoning alone: an indicative timing of the affected rows against main (pinned to the
performance cores), a full BDN run or a profile where the indicative numbers move, and allocation
checks in every gate. Timing runs in an owner-scheduled window and takes the lock; profiling uses the
WPR route. A regression that cannot be avoided is sized, recorded in the register and DECISIONS, and
put to the owner before the merge, as D85's cost was.

**Stopping rule:** two consecutive battery runs with no new root cause on the supported surface (that
is, outside refused combinations), every KNOWN-DEFECTS correctness row fixed or pinned, and the
remaining blind spots listed for the owner. If three consecutive runs each find a root cause in the
same cluster, that cluster goes to the refusal procedure rather than another fix.

**Refusal research starts today, in parallel:** for each cluster (partial matching with lookarounds,
atomic groups or verbs; verbs inside fuzzy sections and lookbehinds; backreferences into repeats;
`\K` in fuzzy or reversed patterns), survey what PCRE2, Perl, Java, .NET, Ruby/Onigmo, Rust
fancy-regex, Boost and TRE do (refuse, restrict, or support), and the usage counts we already have
(`.scratch/s1016/survey/summary.md`). Output: one table per cluster with a recommendation.

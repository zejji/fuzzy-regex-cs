# Decisions

Append-only. One dated line per decision a future session would otherwise have to re-derive.
Never edit or delete an entry: if a decision is reversed, add a new line saying so.

- 2026-08-29 Port target is mrab-regex at `1760a20647f1c2ddcc025128407fe6f7edb905a1` (release 2026.8.12), pinned as the `upstream/` submodule.
- 2026-08-29 SDK pinned to 10.0.400 with `rollForward: latestPatch` in `global.json`; `test.runner` set to Microsoft.Testing.Platform, which TUnit requires on the .NET 10 SDK.
- 2026-08-29 Analyzer set copied from an earlier internal monorepo (Meziantou, SonarAnalyzer, SharpSource, ErrorProne.NET) with warnings as errors, but **not** its `CommunityToolkit.Diagnostics` reference: the shipped package must carry zero runtime dependencies.
- 2026-08-29 Analyzer rules that a faithful port must violate (method length, complexity, nesting, magic numbers, commented-out upstream code, `NotImplementedException`) are relaxed in `.editorconfig` for `src/FuzzyRegex/Parsing` and `Engine` **only**. Correctness and security rules stay as errors everywhere. Rationale: upstream's structure must be preserved for syncs to stay mechanical, and autonomous slice sessions should spend allowance porting, not restructuring to satisfy a style rule.
- 2026-08-29 Test identity for the parity ratchet is `className + "." + testName` from the TRX report; the baseline stores the sorted **set** of passing ids rather than a count, so a slice's diff shows exactly which tests it enabled and a swap cannot hide behind an unchanged total.
- 2026-08-29 Feature area for `docs/STATUS.md` is derived from the test namespace (`FuzzyRegex.Tests.Ported.<Area>`), and the capability a skipped test waits on is parsed from its `[Skip("needs:...")]` reason. Both conventions are enforced by a test (`PortedTestConventionsTests`), because a silent mis-parse would report fake progress.
- 2026-08-29 Budget gate: validated that **no local source reports live plan utilisation**. `~/.claude/stats-cache.json` lags by weeks and has no plan denominator; a `rateLimit` record appears only after a request has already been rejected (429); the claude.ai usage page needs an interactive browser, which an unattended `claude -p` driver has not got. The gate is therefore the deterministic slice caps (spec section 9's sanctioned fallback), plus rolling 24h/7d token windows computed from `~/.claude/projects/**/*.jsonl`, plus a back-off while a recorded rate-limit reset is still in the future.
- 2026-08-29 Budget token metric is the plain sum of all four token types, cache reads included, counted **globally** across every Claude Code session on the machine. Measured that day: about 2.9e9 tokens/day and 1.98e10/week.
- 2026-08-29 Token caps are a **circuit breaker, not a rationing mechanism**; the slice caps do the rationing. Setting the token caps at half of typical usage was tried and rejected: a dry run of the driver refused the very first slice, because an ordinary working day passes that mark by the afternoon. They now sit at roughly 2x the measured daily figure so they only trip on a runaway.
- 2026-08-29 `check-ratchet.ps1 -AcceptRemovals` is the only sanctioned way to retire a baselined test. A rename and a lost test look identical from outside, so removals go red by default; accepting them lists each one. Hand-editing `tests/parity-baseline.json` is forbidden because it would let real coverage loss through unnoticed.
- 2026-08-29 Skip reasons name a **capability** (`needs:lookbehind`), not a slice id, and Phase 1 opens with an API surface stub (slice S01). Both resolve contradictions in the design spec as originally written; the spec is amended inline and the changes are listed in its section 15.
- 2026-08-29 Per-slice cost is measured from `claude -p --output-format json`, which returns `usage`, `total_cost_usd`, `is_error` and `permission_denials` - more reliable than scraping session logs.
- 2026-08-29 The driver passes a scoped tool allowlist (Read/Write/Edit/Glob/Grep/TodoWrite/Skill/Task/Agent and Bash limited to dotnet, git, pwsh and python) with `--permission-mode acceptEdits`. No blanket permission bypass: an unattended session must not be able to run arbitrary commands on the machine.
- 2026-08-29 Python oracle runs `regex` **2026.7.19** from PyPI locally; the pinned submodule commit is tagged 2026.8.12, which upstream never published. **The gap is immaterial and this is measured, not assumed**: `git diff 0525aff..1760a20` (the 2026.7.19 tag to the pin) touches only `pyproject.toml`, `changelog.txt`, `.github/workflows/main.yml` and the `__version__` string in `regex/_main.py`. `src/_regex.c`, `src/_regex_unicode.c`, `regex/_regex_core.py` and `regex/tests/test_regex.py` are byte-identical, so matching behaviour is the same. Re-run that diff before trusting this at the next sync.
- 2026-08-29 The oracle in CI is **built from `upstream/`**, not installed from PyPI, so the ground truth is exactly the pinned commit; the Linux runners already have a compiler, so it costs nothing. `oracle.yml` asserts the built version equals the version in `upstream/pyproject.toml` - a silently mismatched oracle would report version drift as port defects. Verified the assertion has teeth by running it against the local 2026.7.19: it fails.
- 2026-08-29 **No C compiler installed on the Windows dev box**, deliberately. There is no MSVC at all, so a local from-source build means 3-7 GB of VS Build Tools, and for the current pin it would buy nothing but a different version string. Install it at the first upstream sync where the pinned commit genuinely differs from a published release - `sync-upstream` says how and when.
- 2026-08-29 Pester 6.1.0 installed for the PowerShell tooling tests (only the Windows-bundled Pester 3.4.0 was present, whose syntax is incompatible).
- 2026-08-29 `docs/STATUS.md` carries no timestamp and is written with LF endings, and `.gitattributes` sets `eol=lf` repo-wide. CI regenerates the board and fails on any diff; a wall-clock stamp made that check fail on every run, and a CRLF/LF flip rewrote every line on the Linux and macOS legs.
- 2026-08-29 `docs/plan/slice-log.jsonl` is gitignored. The budget gate counts slices from it, and the failed-slice rollback runs `git clean -fd`, which would have deleted it and reset the driver's daily cap to zero. Verified that `git clean -fd` (no `-x`) leaves ignored files alone.
- 2026-08-29 The driver launches `claude` through `ProcessStartInfo.ArgumentList`, not `Start-Process -ArgumentList`. The latter joins arguments with spaces and quotes nothing, so `Bash(dotnet *)` reached the CLI as two tokens and the scoped allowlist - the whole safety boundary for an unattended session - silently did not apply.
- 2026-08-29 A failed slice rolls back to the head recorded before the session, not to `HEAD`. A session can commit its work and move its slice file to `done/` and still leave the ratchet red; resetting to `HEAD` kept that commit and stranded the slice where it would never be retried.
- 2026-08-29 The editorconfig section for the port relaxations is `[src/FuzzyRegex/{Parsing,Engine}/**.cs]`. The obvious `**/*.cs` form requires an intervening directory, so it matched nothing directly inside `Parsing/` or `Engine/` - exactly where the ported engine lives - and every relaxation was inert. Verified with a probe file before and after.
- 2026-08-29 Phase 0 closed with a blind review that found eight defects, all confirmed and fixed. Five were in the slice driver and the ratchet, none would have been caught by the tests as they stood, and each fix that had testable logic gained a test. Worth repeating per slice as the spec requires.
